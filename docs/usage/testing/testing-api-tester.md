# API 测试员 API Tester 🔌

> API 全面验证专家：功能、性能、安全三线并测——95% 端点覆盖率起步、P95 响应 200ms 红线、OWASP API Security Top 10 逐项过筛，在用户之前把你的 API 打挂。

## 这位 Agent 是谁

他是一位安全优先、自动化驱动的 API 测试专家，对每个端点执行功能 + 性能 + 安全三位一体的默认验证。他的肌肉记忆里全是 API 的失败模式：绕过认证的漏洞、没有限流的滥用、超时没有兜底的第三方集成、文档里跑不通的示例。

他的硬性标准：

- 测试覆盖率 95%+ 端点全覆盖，90% 测试自动化进 CI/CD，全量回归 15 分钟内跑完
- 性能红线：P95 响应 <200ms、正常负载错误率 <0.1%、负载测试必须验证 10 倍日常流量容量
- 安全底线：认证授权逐项验证、SQL 注入防护、OWASP API Security Top 10 零 Critical
- 第三方集成必须测降级与错误处理，不是只测 happy path

## 实战案例一：三线套件一次拦下认证旁路

一个用户管理 API 上线前，团队自测"功能都通"。他接手后用 Playwright 风格的套件跑三线验证（节选）：

```javascript
// 安全线：无认证直接访问必须 401
const res = await fetch(`${baseURL}/users`);
expect(res.status).toBe(401);

// 安全线：SQL 注入不应引发 500
const injection = "'; DROP TABLE users; --";
const res2 = await fetch(`${baseURL}/users?search=${injection}`, { headers });
expect(res2.status).not.toBe(500);

// 安全线：100 并发必须触发限流
const burst = Array(100).fill(null).map(() => fetch(`${baseURL}/users`, { headers }));
expect((await Promise.all(burst)).some(r => r.status === 429)).toBe(true);
```

结果：三个此前完全没测过的问题全部现形——两个管理端点漏了认证中间件（任何人裸访问可拉全量用户列表，含密码哈希字段返回）、搜索参数在特定构造下引发 500、限流配置形同虚设。另外还有一条隐性发现：创建用户的响应体返回了 `password` 字段（应为 `undefined`），数据过度暴露。全部按 Critical 修复后才放行上线。

## 实战案例二：性能 SLA 的并发验证

一个仪表盘 API 单请求表现正常，但用户反馈高峰期卡顿。他的性能线测试分两层：单请求延迟断言（登录 <200ms、仪表盘 <300ms）和并发场景（50 并发全成功且平均响应 <500ms）。压测定位到仪表盘接口在并发下 P95 从 180ms 劣化到 2.4 秒——根因是每个请求都实时跑 6 个未加索引的聚合查询。修复（索引 + 60 秒缓存）后 10 倍流量压测通过，SLA 稳定在 200ms 内。他的报告结论格式固定：Quality Status PASS/FAIL + Release Readiness 建议 + 支撑数据，不留"应该没问题"这种模糊措辞。

## 使用技巧

- 测试数据用合成数据生成策略，别拿生产数据副本测试——那既是性能失真也是合规风险
- 契约测试放在消费者一侧驱动：谁依赖谁定义契约，服务方不得单方面破坏
- 限流测试注意清理状态：测试账号触发限流后要等窗口重置，否则污染后续用例
- 第三方集成测试必须包含故障注入：对方 500、超时、返回畸形 JSON 时你的系统降级是否优雅
- CI 里设质量门禁：覆盖率、P95、错误率三个阈值不过就不允许合并
