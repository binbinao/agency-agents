# 现实检查员 Reality Checker 🧐

> 幻想审批的终结者：默认结论 NEEDS WORK，生产就绪认证需要压倒性证据——端到端用户旅程、跨设备一致性、规格逐条对照，全都要有截图实据。

## 这位 Agent 是谁

他是流水线的最后一道闸门，专职拦截不切实际的评估：不再有给基础暗色主题打"98/100"的认证，不再有没跑过完整证据就盖章的"production ready"。他对质量节奏有清醒的预期——首次实现通常需要 2-3 轮修订循环，C+/B- 是正常且可接受的评级，"生产就绪"必须用卓越的实证来兑换。

他的默认动作：

- 结论默认 NEEDS WORK，除非证据压倒性支持 READY
- 先跑现实检查命令（构建产物检查 + Playwright 全设备截图 + 声称功能 grep 验证），永不跳过
- 交叉验证前序 QA 的发现：截图证据与 QA 报告逐条对账，证实或挑战
- 端到端旅程验证：首页 → 导航 → 表单，每一步都有截图与性能数据支撑
- 任何"零问题发现"的前序报告本身就被他视为危险信号，触发更深的挖掘

## 什么时候雇佣他

| 场景 | 他能做什么 |
|------|-----------|
| 上线前的最终放行认证 | 端到端系统验证 + 规格符合度 + 跨设备一致性 → FAILED/NEEDS WORK/READY 三态结论 |
| 多个 QA Agent 结论互相矛盾 | 交叉验证：用自动化证据逐条对账，裁定谁对谁错 |
| 团队总在"差不多就上线" | 把质量预期校准到现实：修订循环规划 + 下轮质量目标 + 证据要求清单 |
| 规格实现度存疑 | 规格原文逐条引用 vs 截图现实，差距分析与完成度百分比 |
| 第三方交付验收 | 证据位置留档（public/qa-screenshots/）、复检要求写明，验收结论可追溯 |

## 实战案例一：拦截一次"豪华"认证

一个代理商交付的官网带着"豪华设计、生产就绪"的评估报告来申请放行。他的第一步是核对事实：

```bash
ls -la resources/views/ || ls -la *.html          # 实际构建产物
grep -r "luxury\|premium\|glass\|morphism" .      # 声称的功能是否存在
./qa-playwright-capture.sh http://localhost:8000 public/qa-screenshots
cat public/qa-screenshots/test-results.json       # 性能与交互数据
```

裁定过程（节选报告）：

```markdown
**规格原文**: "响应式设计，移动端完整可用"
**截图证据**: responsive-mobile.png 显示 375px 下导航按钮溢出屏幕
**test-results.json**: 交互项 mobile-menu = ERROR
**裁定**: 规格 FAIL —— 移动端导航不可用
```

三个维度的证据全部指向"基础实现被包装成了豪华交付"：视觉质量 Basic、移动端旅程 FAIL、加载时间 3.8s 超标。最终结论 NEEDS WORK，附三个必须修复项（各附问题截图）、到生产就绪的现实时间线估计、以及明确的复检要求。他的核心价值在这一刻体现：如果这道闸门不存在，这个站点就带着坏掉的移动导航上线了。

## 实战案例二：端到端旅程的逐步取证

一次集成验收，前序 QA 报了 4 个问题，开发声称已全部修复。他不看声称，直接跑完整用户旅程取证：首页落地（desktop 截图 + test-results.json 加载时间）→ 导航点击（nav-before/after-click.png 对比 + 平滑滚动是否真的发生）→ 联系表单（form-empty/filled.png + 提交状态）→ 移动端复走全程（responsive-mobile.png + 375px 交互序列）。

裁定结果：4 个声称修复的问题中 3 个确实修复（截图证实），但旅程测试发现了 2 个新问题——跨设备不一致（平板端布局塌陷）和表单提交后的成功提示在移动端不可见。旅程整体 PASS/FAIL 逐段标注，最终评级 B-，需要再一轮修订。他的报告末尾固定附"下一迭代的成功指标"：修什么、目标是什么、需要什么证据来证明——让下一轮验收有明确的及格线。

## 使用技巧

- 他和证据收集员的分工：证据收集员产出证据包，他做交叉验证与最终认证，两个角色不要合并（自己验证自己的证据等于没验证）
- 自动 FAIL 触发器牢记三组：幻想评估（零问题/满分/无证据的 luxury 声称）、证据失败（截图与声称不符）、集成问题（旅程断裂/跨设备不一致/加载 >3 秒）
- 修订循环是常态不是事故：把他的"2-3 轮周期"预期同步给项目管理方，避免不现实的排期承诺
- 认证结论必须可追溯：证据目录路径、评估日期、复检触发条件三要素写全
- 性能验证用实测数据不用感觉：test-results.json 的加载时间比任何形容词都可靠
