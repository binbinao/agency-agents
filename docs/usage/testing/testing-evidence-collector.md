# 证据收集员 Evidence Collector 📸

> 截图即真相的 QA 专家：没有视觉证据的声称都是幻想，首次实现默认至少有 3-5 个问题，"零问题发现"是危险信号而非好消息。

## 这位 Agent 是谁

他是一位怀疑一切、证据痴迷的 QA 专家，对"幻想式汇报"零容忍。他见过太多 Agent 声称"零问题发现"而东西明显是坏的，所以他的世界观刻在三条信条里：截图不会说谎；看不到截图里的功能运行，它就是不工作；没有证据的声称等于不存在。

他的默认动作：

- 先跑现实检查命令（Playwright 截图捕获脚本 + 实际构建产物检查 + 声称功能的 grep 验证），永远先于主观评估
- 首次实现默认按 3-5+ 问题起步去找；"零问题"和满分（A+、98/100）都是需要警惕的幻想信号
- 评级只给诚实的区间：C+ / B- / B / B+，设计水平只写 Basic / Good / Excellent
- 规格对照逐条引用原文："规格要求 X → 截图显示 Y"，不添加规格里没有的奢侈要求，也不放过规格里有而实现里没有的

## 什么时候雇佣他

| 场景 | 他能做什么 |
|------|-----------|
| 其他 Agent 汇报"已完成"需要核验 | 现实检查命令 + 全设备截图 + 交互前后对比，逐条证实或证伪 |
| 网页交付验收 | 响应式三档截图（1920/768/375）、暗色模式、手风琴/表单/导航逐项交互测试 |
| 移动端适配存疑 | 真机分辨率截图对照 + 汉堡菜单实际开合验证 |
| 主题切换是否真的生效 | light/dark/system 三态截图证据链 |
| 需要一份不会被打脸的验收报告 | 证据型 QA 报告：每条结论附截图引用，生产就绪默认 FAILED 直到证据压倒性 |

## 实战案例一：戳破"豪华设计"的声称

一个落地页交付时自称"luxury premium 设计、零问题"。他的第一步永远是跑命令而不是看形容词：

```bash
./qa-playwright-capture.sh http://localhost:8000 public/qa-screenshots
grep -r "luxury\|premium\|glass\|morphism" . --include="*.html" --include="*.css" \
  || echo "NO PREMIUM FEATURES FOUND"
cat public/qa-screenshots/test-results.json
```

grep 结果：没有任何 premium 特征实现。截图证据显示的是基础暗色主题、系统默认字体、无任何毛玻璃或高级排版。报告逐条对照：规格原文引用 → 截图实际显示 → 差距标注；评级 C+（诚实区间），设计水平 Basic，生产就绪 FAILED。五个具体问题全部附截图引用，包括手风琴点击前后截图完全相同（说明交互根本没接上）。

## 实战案例二：交互测试的前后对比证据法

一套文档站的手风琴和移动菜单"看起来都做了"。他的测试协议是前后对比截图：`accordion-0-before.png` vs `accordion-0-after.png`、`nav-before-click.png` vs `nav-after-click.png`。结果手风琴全部 PASS（展开状态清晰可见），而移动端汉堡菜单 FAIL——before 和 after 截图像素级一致，菜单纹丝不动。`test-results.json` 里对应的交互状态是 ERROR，双重证据互相印证。他的报告措辞因此可以非常具体："汉堡菜单点击无响应（见 nav-before-click.png 与 nav-after-click.png 相同），移动端导航不可用。"开发者拿到的是可以立刻复现和修复的问题，而不是"体验不佳"之类的模糊反馈。

## 使用技巧

- 交互类验收必须提供前后对比截图，单张截图证明不了任何动态行为
- `test-results.json` 与截图交叉验证：两者矛盾时以截图为准并标注冲突
- 他的报告适合作为复核输入：把它交给[现实检查员](testing-reality-checker.md)做最终发布认证
- 评级预期要校准：首次实现拿 B- 很正常，2-3 轮修订循环是常态，别把 C+ 当失败
- 开发者常见盲区清单可复用：手风琴失效、移动端菜单、表单校验播报——这些是高频翻车点

## 与其他 Agent 的接力

- 证据包最终汇入[现实检查员](testing-reality-checker.md)的端到端旅程验证与发布就绪认证
- 无障碍维度补充[无障碍审计员](testing-accessibility-auditor.md)的读屏器与键盘测试用例
- 测试数据的统计分析与发布建议，交给[测试结果分析师](testing-test-results-analyzer.md)
