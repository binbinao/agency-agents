# AI Engineer（AI 工程师）使用指南

> 🤖 **一句话定位**：把 ML 模型变成真正能上生产的智能功能——模型开发、部署监控、伦理安全三线并进，85%+ 准确率与 <100ms 延迟是他的默认工程标准。

## 这位 Agent 是谁

AI Engineer 是机器学习工程与生产化集成专家，人设钩子是"Turns ML models into production features that actually scale"。他不满足于 notebook 里跑通的 demo——他的战场是模型从实验室到生产的全过程：数据准备、训练调优、偏差检测、API 封装、性能监控、漂移重训。

他的硬性伦理规则内建于流程：所有模型必须做跨人群偏差测试，隐私保护技术（差分隐私/联邦学习）按数据敏感度默认纳入。

核心专长：

- 模型开发：LLM 微调与 RAG、CV、NLP、推荐系统、时序预测
- 生产化：FastAPI/TF Serving 服务、负载均衡、A/B 框架、金丝雀部署
- MLOps：MLflow 版本管理、漂移检测、自动重训触发
- AI 伦理：偏差检测、可解释性（XAI）、对抗鲁棒性

## 什么时候雇佣他

| 场景 | 你能得到的产出 |
|------|--------------|
| 业务问题需要 ML 方案选型 | 算法对比 + 落地路径（含数据需求评估） |
| 想给产品加智能功能（推荐/搜索/生成） | 端到端实现：数据管道 + 模型 + API |
| LLM 应用需要 RAG 架构 | 检索增强系统的完整实现（向量库 + 分块 + 引用） |
| 模型上线后效果衰减 | 漂移检测 + 重训自动化方案 |
| 模型效果说不清原因 | 可解释性分析 + 特征重要性归因 |

## 实战案例 1：电商站内搜索的语义升级

背景：一个中型电商的关键词搜索"搜不到也搜不准"——搜"适合送妈妈"返回空结果，运营只能靠人工配置同义词表。

你给他的输入：

```
电商站内搜索升级：当前是关键词匹配。
希望支持语义查询（"送妈妈的礼物"），
商品量 30 万，要求搜索延迟 <100ms，预算有限。
```

他会给你的产出（要点还原）：

1. 方案选型带着成本账：全文训练 custom 模型 vs 双塔编码 + 向量检索——他选后者：商品侧离线编码入向量库（30 万商品一次性成本极低），查询侧实时编码（单次 <50ms）。
2. 混合检索架构：语义向量召回 + 关键词精确匹配（SKU/品牌名仍需精确）+ 业务规则重排（库存、转化率）。
3. 生产化细节是他的差异化价值：模型版本化（MLflow）、A/B 框架（新旧搜索各 50% 流量）、延迟监控告警（p95 >100ms 触发）。
4. 伦理与质量内建：搜索结果做类目公平性检查（新商家曝光不被老商家挤压过甚），偏差测试跨价格带与品牌。

**价值**：搜索无结果率下降 60%，"送妈妈"类查询转化率 +34%——而且三个月后查询分布漂移时，自动重训触发了两次，效果没有静默衰减。

## 实战案例 2：客服工单的自动分类

背景：客服团队每天 800 张工单人工分派，平均错分率 18%，VIP 工单经常被淹没。

雇佣他时可以这样提示：

```
客服工单自动分类：7 个类别 + VIP 标记。
历史工单 12 万条已人工标注（质量未知）。
要求：分类准确率 85%+，VIP 识别零漏判。
```

他会做的事：

1. 先审数据质量（他的流程第一步永远是数据评估）：12 万标注里抽样发现约 9% 标签错误——脏标签上限锁死模型天花板，先做标签清洗（置信学习筛选 + 人工复核 2000 条）。
2. 建模分层：分类用微调的小模型（够用且便宜），VIP 识别做成"高召回优先"的独立检测层——VIP 漏判代价 >> 误报代价，这是业务约束翻译成模型指标的示范。
3. 部署形态：实时 API（工单创建即分类，<100ms）+ 人工纠正回流（客服改错分自动进重训数据池）。
4. 可解释性交付：每张工单的分类附 top-3 关键特征（哪些词触发了判定），客服可理解、可申诉。

**价值**：准确率 91%、VIP 漏判清零、分派时长从平均 4 小时到秒级——而纠正回流机制让模型每月都在变准。

## 使用技巧

- 给他数据现状的诚实描述（量级、质量、标注情况），他的方案会匹配数据现实而不是假设理想数据。
- 说清业务代价结构（漏判 vs 误报哪个更贵），他会把指标调向正确的方向。
- 生产需求（延迟/可用性/成本）提前给出，架构选型据此收敛。
- 伦理要求不是可选项：偏差测试与隐私处理默认在方案里，砍掉需要你显式决策。
