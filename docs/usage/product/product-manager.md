# Product Manager（产品经理）使用指南

> 🧭 **一句话定位**：把模糊的"我们该做个 X"变成有证据、有指标、有边界的可执行需求——连续追问三层"为什么"是他的开场动作。

## 这位 Agent 是谁

Product Manager 是产品发现与定义专家。他的方法论核心是"问题先于方案"：接手任何需求，先做机会评估（Opportunity Assessment）——为什么做、为什么现在做、为什么是我们做——然后才写 PRD。他的 PRD 有个鲜明特征：明确写出"不做什么"，每条都附理由，把范围蠕变挡在文档阶段。

核心专长：

- 需求发现：客户访谈、连续追问（Five Whys 式）、问题定义
- 机会评估：RICE 评分、市场窗口判断、竞品对照
- PRD 撰写：问题陈述、成功指标、用户故事、验收标准
- 发布管理：内测→封测→灰度→全量的分阶段计划与回滚标准

## 什么时候雇佣他

| 场景 | 你能得到的产出 |
|------|--------------|
| 高管/客户丢来一句"做个 X" | 机会评估 + 三层追问后的真实问题定义 |
| 需求文档没人看得懂或有歧义 | 结构化 PRD（含验收标准与边界） |
| 功能做完不知道算不算成功 | 可量化的成功指标定义与埋点要求 |
| 上线节奏心里没底 | 分阶段发布计划与回滚标准 |
| 范围总在开发中途膨胀 | "不做什么"清单 + 变更影响评估流程 |

## 实战案例 1：把"商家想要优惠券"变成真需求

背景：这是跨部门工程故事的第一幕——星舟科技收到高频客服信号："商家想要优惠券"。

他会做的事（要点还原）：

1. 三层追问：

```markdown
为什么商家要这个？→ 访谈 8 家商家：真实诉求是唤回 30 天未下单的老客户，
  折扣只是他们想象的解法。
为什么是现在？→ 工单 120 张/月占总量 15%，双十一前 6 周是最后开发窗口。
为什么是我们做？→ 竞品已有基础券能力，churn 访谈中 3 家商家因此转向。
```

2. RICE 打分后结论 Build，但明确范围边界：

```markdown
## 我们不做什么（v1）
- 满减券：受访商家无人主动提及，留待 v2 验证
- 分享裂变券：涉及风控与合规，超出本期风险预算
- 券模板市场：供给侧不成立（商家量 < 1000）
```

3. 成功指标可验证：老客 30 天回访率 42% → 55%（数据来源：订单表回流查询，无需新埋点）。

**价值**：没有这一幕，工程团队会直接做"优惠券 CRUD"；有了这一幕，他们做的是"老客唤回工具"——同一个词，完全不同的产品。

## 实战案例 2：为模糊的"提升活跃度"定靶

背景：CEO 在 OKR 里写"Q3 提升 DAU 30%"，团队不知道从哪下手。

雇佣他时可以这样提示：

```
CEO 目标：Q3 DAU +30%。目前只有目标没有路径。
请把这个目标翻译成可执行的产品策略。
```

他会做的事：

1. 先拆解问题：DAU = 新增激活 + 存留 + 召回。当前数据结构下哪个杠杆最大？拉数据发现 30 天召回率仅 18%，而行业基准 35%——杠杆找到了。
2. 把大目标翻译成假设树："如果老客收到基于其消费历史的个性化召回，30 天回流率可提升至 30%"+ 三条候选路径（召回券/内容推送/订阅提醒）。
3. 每条路径给出验证成本最低的实验设计（先 5% 流量 A/B，两周出结论）。
4. 输出一页纸战略摘要：目标 → 杠杆 → 假设 → 实验 → 指标，CEO 与工程师都能看懂。

**价值**：把"口号式 OKR"变成"假设驱动、可实验、可证伪"的产品路径。

## 使用技巧

- 给他原始信号（工单、访谈记录、数据截图）而不是加工过的结论，他的追问才有原料。
- 期待他挑战需求前提，这是流程的一部分；被挑战掉的需求往往是省下的开发成本。
- PRD 的"不做什么"部分请认真评审——那是范围蠕变的第一道防线。
- 成功指标要与他约定数据来源，避免上线后才发现指标不可测。
