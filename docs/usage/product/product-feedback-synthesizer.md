# Feedback Synthesizer（反馈综合分析师）使用指南

> 🔍 **一句话定位**：把一千条用户声音蒸馏成你下一步该做的五件事——多渠道反馈收集、主题编码、RICE 排序，输出的是决策而不是报表。

## 这位 Agent 是谁

Feedback Synthesizer 是用户反馈收集与分析专家，人设钩子就是"Distills a thousand user voices into the five things you need to build next"。他的价值在于把散落在问卷、工单、应用商店评论、社媒、社区论坛里的原始反馈，加工成带优先级、带置信度、带原话引用的产品洞察。

核心专长：

- 多渠道采集：主动渠道（问卷/访谈）、被动渠道（行为分析/热图）、社区渠道（论坛/Discord/Reddit）、竞品渠道（评论挖掘）
- 主题分析与情感分析：NLP 情绪检测、主题标签、置信度评分
- 量化转化：定性反馈 → RICE/MoSCoW/Kano 优先级矩阵
- 流失预警：基于反馈模式与满意度建模的早期预警
- 分受众交付：高管看仪表盘、产品团队看用户故事、客服团队看处置手册

## 什么时候雇佣他

| 场景 | 你能得到的产出 |
|------|--------------|
| 反馈散落各渠道，没人有全局视图 | 全渠道反馈聚合 + 主题分布仪表盘 |
| 用户访谈/工单看完就忘 | 主题编码 + 代表性原话摘录（带上下文） |
| 功能请求一堆，排不出优先级 | RICE 打分的功能请求优先级矩阵 |
| NPS 连续下滑找原因 | 满意度建模 + 与主题的统计相关性分析 |
| 客服被同类问题淹没 | 反馈模式驱动的客服处置 playbook |

## 实战案例 1：应用商店差评的抢救性分析

背景：一款工具 App 近期商店评分从 4.6 跌到 4.1，300 条新差评，运营只回复"亲，已记录"。

你给他的输入：

```
近 30 天应用商店新增 300 条差评（iOS+Android），评分 4.6→4.1。
另有近 200 条客服工单。请分析根因并给出优先级建议。
```

他会给你的产出（要点还原）：

1. 清洗与归一：去重（同一用户多渠道反馈合并）、按版本/平台/用户类型分层。
2. 主题编码——差评不是均匀分布的：

```markdown
主题 1（42%，127 条）：v3.2 后启动崩溃（Android 8 及以下机型集中）
主题 2（23%，69 条）：订阅价格质疑（新老用户价格不同的公平性争议）
主题 3（11%，33 条）：某功能入口找不到（v3.1 改版遗留问题）
```

3. 每个主题配代表性原话与情绪强度，主题 2 的怒值显著高于主题 1（崩溃是失望，价格争议是愤怒——传播风险更高）。
4. RICE 排序建议：崩溃修复 Reach 最高 Confidence 100% 排第一；价格争议的解法是沟通而非功能（出澄清公告 + 老用户锁定价），排在第二但成本极低。
5. 交付分三份：给 CEO 的一页结论、给工程的用户故事（崩溃复现条件已整理成验收标准）、给客服的临时话术。

**价值**：300 条差评从"情绪垃圾"变成三个可执行动作，其中价格澄清公告 48 小时内就止住了评分下滑——不是所有问题都需要写代码。

## 实战案例 2：为路线图评审准备"用户之声弹药"

背景：季度路线图评审会，产品 VP 要求"用数据说话"，但团队手里的用户反馈全是零散截图。

雇佣他时可以这样提示：

```
下周期路线图评审，需要一份基于用户反馈的优先级论证。
可用材料：NPS 调查开放题 500 条、季度访谈 20 场、社区论坛热帖。
```

他会做的事：

1. 三源数据三角验证：一个主题只在 NPS 开放题出现，证据弱；同时出现在访谈原话与论坛热帖，证据强——每个结论标注置信度。
2. 识别边界情况：论坛声量最大的诉求来自 3% 的 power user，而访谈显示沉默的大多数完全不在乎——声量 ≠ 优先级，这是偏差检测的价值。
3. 流失预警建模：提及"正在评估竞品"的用户画像特征汇总，标记 37 个高风险账户清单给客户成功团队。
4. 产出评审会直接可用的优先级矩阵与用户故事草稿，85% 的洞察直接进入决策（这是他的成功指标）。

**价值**：路线图评审从"谁嗓门大听谁的"变成"证据置信度排序"。

## 使用技巧

- 把你能拿到的原始数据都给他（导出的 CSV、访谈记录、截图），他的三角验证依赖多源数据。
- 明确告知本次分析的服务对象（高管/产品/客服），他会切换交付格式。
- 反馈量大时先说紧急程度：关键问题他的处理时效是 24 小时内。
- 对"声量大但样本偏"的主题保持警觉，他的偏差检测会标注，但决策时你要看得懂。

- 转化为 PRD 交给 **Product Manager**（`product-product-manager.md`）。
