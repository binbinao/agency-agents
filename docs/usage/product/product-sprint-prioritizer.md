# Sprint Prioritizer（冲刺优先级规划师）使用指南

> 🎯 **一句话定位**：用数据驱动框架（RICE/价值-成本矩阵/Kano）做无情的聚焦——让每个冲刺的承诺都交付 90% 以上。

## 这位 Agent 是谁

Sprint Prioritizer 是敏捷冲刺规划与资源分配专家，人设钩子是"Maximizes sprint value through data-driven prioritization and ruthless focus"。他的世界里没有"都要做"，只有"按框架排序后的取舍 + 显式的 trade-off 记录"。他管的不只是优先级，还有团队容量、依赖关系、技术债配额（20% 容量上限）与交付风险。

核心专长：

- 优先级框架：RICE（含敏感度分析）、Value vs. Effort 矩阵（快赢/大项目/填充/时间黑洞四象限）、Kano 模型（必备/期望/兴奋/无感/反向）
- 容量规划：6 个冲刺滚动速度均值、15-20% 会议假期折减、10-15% 不确定性缓冲
- 依赖管理：跨团队依赖的识别与关键路径分析，95% 依赖要求在冲刺开始前解决
- 干系人对齐：Priority Poker 协作排序、显式的范围-时间 trade-off 谈判记录

## 什么时候雇佣他

| 场景 | 你能得到的产出 |
|------|--------------|
| 待办列表一堆"都重要"，没人敢排 | 框架化排序 + 各方签字的优先级决议 |
| 冲刺承诺经常烂尾 | 容量校准的冲刺计划 + 15% 缓冲策略 |
| 跨团队依赖总在冲刺中途爆炸 | 依赖地图与关键路径提前识别 |
| 新功能与技术债抢资源 | 技术债 ROI 建模与 20% 容量配额方案 |
| 排期估算总被打脸 | 带置信区间的交付预测（±10% 方差目标） |

## 实战案例 1：救一个连续三个冲刺烂尾的团队

背景：某团队近三个冲刺完成率 55%、62%、58%，士气低落，PO 仍在往冲刺里塞需求。

你给他的输入：

```
团队 6 人，近 3 个冲刺完成率 55%/62%/58%。
冲刺容量评估从未做过，PO 每次规划按"感觉"塞 40+ 故事点。
请诊断并给出下个冲刺的可执行规划。
```

他会给你的产出（要点还原）：

1. 先校容量：6 冲刺滚动速度均值 28 点；本月有 1 人休假 3 天、集体培训 1 天 → 折减 18%，实际可用约 23 点；再加 10% 不确定缓冲 → 承诺上限 21 点。
2. 待办按 RICE 排序，并给出敏感度分析："功能 A 与 B 的 RICE 分接近，但 B 依赖平台团队接口（未确认），降级到下个冲刺——依赖未解决的故事不进冲刺，这是 95% 规则。"
3. 显式 trade-off 给 PO："塞进功能 C 的代价是推迟技术债专项，本季度利息（缺陷修复工时）预计 +12 小时/冲刺，签字确认。"
4. 冲刺目标收敛为一句话可衡量的目标，而非一堆故事的集合。

**价值**：下个冲刺完成率 91%——不是团队变强了，是承诺第一次建立在数据上。

## 实战案例 2：Kano 模型救评审会上的"全都要"

背景：季度规划会，销售、客服、市场各提需求，全部标"高优"，会议僵持 3 小时。

雇佣他时可以这样提示：

```
季度规划会僵局：12 个候选需求，三个部门都说自己的最重要。
请提供破局框架与 facilitation 方案。
```

他会做的事：

1. 会前把 12 个需求做 Kano 分类问卷（每个需求问功能式与反向式两个问题），发给 50 个真实用户而不是部门负责人——"必备项缺失会引发不满，兴奋项才是差异化的来源"。
2. 会议用 Priority Poker 协作排序：部门负责人用框架对话而不是嗓门对话。
3. 结果示例：销售力推的需求经 Kano 验证是"无感区"（用户不在乎），当场证据展示；客服提的一个小改动是"快赢象限"（高价值低成本），全员秒同意。
4. 输出带置信度的季度承诺与每个被砍需求的复议条件（什么数据出现时重新评估）。

**价值**：僵局的本质是缺乏共同语言，他提供的框架就是那个语言。

## 使用技巧

- 给他团队近 6 个冲刺的速度数据与成员日历（假期/培训），容量校准才准。
- 跨团队依赖务必提前告知，他的关键路径分析需要依赖信息。
- 接受他给出的 trade-off 记录并真的让干系人签字——文档化的取舍才防得住中途加塞。
- 技术债不要藏起来，他的 ROI 建模会给它一个公正的位置（20% 配额）。
