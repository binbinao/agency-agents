# Behavioral Nudge Engine（行为助推引擎）使用指南

> 🧠 **一句话定位**：用行为心理学把"被动仪表盘"变成"主动教练"——从不发"您有 14 条未读通知"，只发一条当下最该做的低摩擦动作。

## 这位 Agent 是谁

Behavioral Nudge Engine 是行为心理学与习惯养成专家。他改造的是软件的"交互节奏"：什么时候打扰用户、用什么渠道、说什么话、怎么庆祝。他把用户当成需要教练的人而不是待通知的收件箱——像一个懂心理学的私人健身教练，知道什么时候该推一把、什么时候该为微小的胜利庆祝。

他的四条铁律：

- ❌ 禁止任务倾倒：50 条待办绝不展示 50 条，只给最关键的 1 条
- ❌ 禁止不分场合的打断：尊重专注时段与用户偏好的渠道
- ✅ 永远提供"退出式完成"："干得漂亮！再来 5 分钟，还是今天就到这？"
- ✅ 善用默认选项偏差："这封 5 星好评的感谢回复我已经拟好了，直接发送还是改改？"

## 什么时候雇佣他

| 场景 | 你能得到的产出 |
|------|--------------|
| 用户被通知淹没导致流失 | 通知节奏重构（渠道/频率/时点个性化） |
| 任务列表太长用户直接躺平 | 微冲刺（micro-sprint）提示设计与认知负荷切分 |
| 用户完成动作后没有正反馈 | 庆祝文案与即时强化方案 |
| 想提升功能采用但不胁迫 | 退出式架构（opt-out architecture）设计 |
| 不同用户 motivation 类型差异大 | 用户偏好画像（渠道/语气/触发器）与差异化序列 |

## 实战案例 1：抢救被通知吓跑的用户

背景：一款中小企业管理工具，新用户注册后第一周收到 14 条系统通知，7 日留存跌到 22%。

你给他的输入：

```
新用户 7 日留存 22%。流失访谈显示"通知太多太烦"是首因。
注册流程会创建一堆默认开启的提醒。请重构通知策略。
```

他会给你的产出（要点还原）：

1. 第一刀砍掉"未读计数"类通知（他的 Default requirement 明文禁止），替换为单一动作提示：

```typescript
// 原来："您有 14 条未读通知"
// 现在：
{
  channel: 'SMS',  // 该用户 onboarding 时选择的偏好渠道
  message: "嘿！有几条客户跟进待处理。咱们试试 5 分钟内
  清掉几条？我已经把第一条的回复草稿拟好了。开始吗？",
  actionButton: "开始 5 分钟冲刺"
}
```

2. 渠道与时点个性化：onboarding 阶段显式询问偏好（SMS 还是邮件、每日还是每周），并持续学习——用户连续 3 天不点每日 SMS，自主降频并询问是否改周报。
3. 默认偏差的合规运用：草稿先行（"已拟好，发送还是修改？"），用户只需点一次批准，完成动作的摩擦降到最低。
4. 完成后永远是庆祝 + 出口："Nice work! 3 条跟进搞定。再来 5 分钟，还是今天收工？"——不制造无限滚动的负罪感。

**价值**：7 日留存回到 41%——不是功能变多了，是软件第一次学会"怎么跟人说话"。

## 实战案例 2：ADHD 友好型的任务产品设计

背景：一个自由职业者 invoicing 工具，目标用户中大量自雇者有注意力管理困难，月度账单流程的完成率仅 55%。

雇佣他时可以这样提示：

```
月度开票流程 6 个步骤，用户大量中途放弃（完成率 55%）。
用户画像中注意力管理困难者比例高。请用行为设计提升完成率。
```

他会做的事：

1. 认知负荷切分：6 步流程不是简化成 5 步，而是切成 6 个独立的 90 秒微冲刺，每步完成即庆祝——他的 ADHD-friendly 动量构建方法。
2. 时限框定（time-boxing）：借力 Pomodoro 式结构，"接下来 5 分钟只做这一件事"。
3. 动量优先于总量：庆祝"已完成 3/6"，绝口不提"还剩 3 步"——他的原则是庆祝 5 个完成而不是强调 95 个未完成。
4. 中断保护：用户中断后回来，从断点微冲刺继续，不重置不惩罚。

**价值**：完成率 55% → 78%，且客服收到的"我用了很内疚"类反馈消失——好的行为设计连情绪成本都照顾到。

## 使用技巧

- 把用户的偏好数据（渠道选择、活跃时段）给他，个性化是他的核心弹药。
- 想清楚你的产品哪些环节"该推"哪些"该让"，他会用退出式架构设计两者。
- 庆祝文案要配合品牌语气（B2B 严肃产品可用克制的庆祝），他会适配。
- 警惕他帮你规避的坑：通知疲劳是留存杀手，宁可少发一条也不要多发。
