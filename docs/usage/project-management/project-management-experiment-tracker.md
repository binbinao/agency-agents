# Experiment Tracker（实验追踪官）使用指南

> 🧪 **一句话定位**：设计实验、追踪结果、让数据拍板——统计功效先行、95% 置信度门槛、禁止提前偷看结果，是团队的"科学方法守门人"。

## 这位 Agent 是谁

Experiment Tracker 是实验设计与数据驱动决策专家。他管理 A/B 测试、多变量实验与假设验证的全生命周期，信条是"let the data decide"。他的严谨体现在细节：实验前必算样本量与统计功效（80% power），禁止无规则提前终止实验（peeking 是数据诚信问题），多组对比必做多重比较校正。

核心专长：

- 实验设计：可证伪的假设、主指标 + 护栏指标、对照组随机化
- 统计执行：样本量计算、置信区间、效应量、p 值解读
- 安全与伦理：护栏监控、回滚预案、用户隐私合规（GDPR/CCPA）
- 组合管理：多实验并发的资源分配与实验间干扰检测
- 决策交付：Go/No-Go 建议 + 证据 + 后续实验路线

## 什么时候雇佣他

| 场景 | 你能得到的产出 |
|------|--------------|
| 想验证一个产品假设但不会设计实验 | 实验设计文档（假设/样本量/时长/风险预案）|
| A/B 测试跑了三天就想看结论 | 功效分析与"为什么不能提前看"的量化解释 |
| 多个实验同时在跑互相干扰 | 实验组合管理与干扰检测 |
| 实验结果解读公说婆说 | 带置信区间的效应量 + 分段分析 + Go/No-Go |
| 上线新功能怕出事 | 带护栏监控与自动回滚的灰度发布设计 |

## 实战案例 1：一个"直觉很好"的实验被拦下重设计

背景：增长团队想在结账页加紧迫感文案（"仅剩 3 件！"），坚信会提升转化，打算 5% 流量跑三天看数据。

你给他的输入：

```
假设：结账页加稀缺性提示可提升转化率。
计划：5% 流量 A/B，3 天后看结果决定全量。
```

他会给你的产出（要点还原）：

1. 先审假设：可证伪 ✓，但主指标要钉死——"转化率"是加购到支付，还是进站到支付？口径不同结论完全不同。
2. 样本量计算推翻原计划：基线转化率 3.2%，期望提升 8%（相对），检出该效应需要每组约 41,000 用户；5% 流量 x 3 天只有约 9,000/组——功效不足 35%，跑了等于白跑。修正方案：20% 流量 x 14 天。
3. 护栏指标设计（他的招牌）：转化率可能升，但退货率、客单价、客诉是护栏——紧迫感可能刺激冲动购买推高退货，"赢了转化输了利润"是他要防的。
4. 明确禁止中途偷看：提前查看 p 值会显著推高假阳性；如果一定要中期决策，改用序贯检验（sequential testing）的统计框架，而不是"忍不住看一眼"。

**价值**：这个实验原方案有约 1/3 概率"测出"根本不存在的效果——他拦截的不是进度，是一次未来的错误决策。

## 实战案例 2：实验结果的"分段真相"

背景：一次 A/B 测试整体结果平淡（+1.2%，不显著），团队准备宣布失败并关闭功能。

雇佣他时可以这样提示：

```
实验整体不显著，准备关掉功能。
请做最终分析，确认没有遗漏。
```

他会做的事：

1. 整体效应 +1.2% CI [-0.8%, +3.1%]，确实不显著——但他的流程必做分段分析。
2. 分段发现：新用户段 +4.7%（显著），老用户段 -1.9%——功能对新用户有效，对老用户是干扰。
3. 修正结论不是"关掉"而是"只对新用户启用"——单个 Go/No-Go 掩盖了异质性效应。
4. 产出学习文档入知识库："稀缺性提示对新用户有效（学习 1）；对习惯用户产生不信任感（学习 2，附用户反馈引用）"——他的组合视角：失败实验也是组织资产。
5. 后续实验建议：新用户专用的更激进变体测试。

**价值**：同一份数据，从"宣布失败"变成"发现新用户增长杠杆"——分段分析是他的标准动作，不是运气。

## 使用技巧

- 给他基线指标数据（当前转化率、流量），样本量计算需要这些输入。
- 说清实验的决策后果（全量 or 关闭），他的显著性门槛与护栏设计据此校准。
- 尊重"不要中途看数据"的规则，如需中途决策让他上序贯检验。
- 实验结束要他的学习文档——单次实验的结论会过期，模式库的复利不会。
