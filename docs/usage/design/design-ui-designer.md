# UI Designer（UI 设计师）使用指南

> 🎨 **一句话定位**：像素级执行的设计系统构建者——把设计 token、组件规范和无障碍标准做成前端可直接映射的界面设计。

## 这位 Agent 是谁

UI Designer 是界面设计与设计系统专家。他的工作方式不是"打开 Figma 随手画"，而是先立系统（色板、字阶、间距、组件规范），再基于系统出界面。他交付的每个界面都自带无障碍标注（对比度、触控目标、状态指示），让前端实现时不需要"猜"。

核心专长：

- 设计系统建设：design token（色彩/字阶/间距）、组件库规范、状态定义（default/hover/focus/disabled）
- 高保真界面设计：响应式布局、多断点适配
- 无障碍内建：WCAG 2.1 AA 对比度、非纯色彩的状态传达、44px 触控目标
- 设计-开发交接：标注清晰到前端可以 token 对 token 实现

## 什么时候雇佣他

| 场景 | 你能得到的产出 |
|------|--------------|
| 产品界面视觉碎片化 | 一版设计 token + 组件规范，统一全局 |
| 新功能需要界面设计 | 带无障碍标注的高保真设计稿 |
| 设计稿交给前端总是走样 | 前端可直接映射的标注体系（token 命名与 CSS 变量对应） |
| 界面可用但"廉价" | 基于间距/字阶/层级系统的视觉升级 |
| 暗色模式支持 | 双主题 token 方案与状态适配 |

## 实战案例：电商优惠券功能的界面系统

背景：这是跨部门工程故事里的真实一幕——星舟科技商家后台各页面视觉碎片化，优惠券功能是补设计系统欠账的契机。

你给他的输入：

```
商家后台要新增「优惠券」功能界面：券创建表单、券列表、发放记录。
现状：各页面按钮颜色、间距、字号各自为政。
请先落设计系统，再出界面。
```

他会给你的产出（要点还原）：

1. 先补系统欠账，token 层先行：

```css
/* 色板：主色/辅色/中性色阶 + 语义色（成功/警告/危险） */
--color-primary-500: #2E5AAC;
--color-text-secondary: #6C757D;
--space-1: 4px; --space-2: 8px; /* 8px 间距系统 */
/* 字阶：12/14/16/20/24/30px 层级 */
```

2. 组件规范：按钮（primary/secondary/ghost 三态）、表单（含错误态与帮助文本）、状态徽章（已发放/已使用/已过期）、表格（斑马纹、固定表头、行 hover）。
3. 优惠券界面全部走 token：券列表页的状态徽章不是三种颜色完事，而是"图标 + 文字"双通道传达（色盲用户也能区分）。
4. 无障碍标注随图交付：对比度 4.5:1 卡线、触控目标 44px、焦点环可见——前端照着实现即可，无需查 WCAG 原文。

**价值**：优惠券界面上线后，后续任何新页面都有了现成的 token 与组件规范——设计系统的复利从这一单开始。

## 使用技巧

- 给他现有产品的截图或品牌规范，他的 token 会向现状收敛而不是凭空发明（除非你明确要视觉重做）。
- 说明目标平台（Web/iOS/Android）与最低设备，触控目标和断点策略据此调整。
- 他的状态定义（hover/focus/disabled/error）是交付的一部分，别在验收时只看默认态。
- 与前端约定 token 命名后再开工，可以实现"设计 token = CSS 变量"的直接映射。

## 与其他 Agent 的接力

- 品牌色板与调性来自 **Brand Guardian**（`design-brand-guardian.md`），他负责将其落地为产品级设计系统。
- 信息架构与交互流程的上游是 **UX Architect**（`design-ux-architect.md`）。
- 设计稿的实现交给 **Frontend Developer**（`engineering-frontend-developer.md`），token 对 token 映射。
- 界面假设需要用户验证时，转给 **UX Researcher**（`design-ux-researcher.md`）做可用性测试。
- 完整的接力案例，见[跨部门工程故事：一个功能从想法到上线](../story-cross-team-feature.md)。
