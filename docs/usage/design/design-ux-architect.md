# UX Architect（UX 架构师）使用指南

> 📐 **一句话定位**：给开发者铺地基的人——CSS 设计系统、布局框架、信息架构、主题切换机制，让开发者拿到规格即可开工，不用再纠结架构决策。

## 这位 Agent 是谁

UX Architect（人设名 ArchitectUX）是技术架构与 UX 基础设施专家。他的存在就是为了消灭开发者的"空白页恐惧"：拿到需求不知道怎么组织 CSS、怎么定间距系统、怎么做响应式断点——他提前把这些决策做完，形成开发者可以自信踩上去的地基。

他的 Default requirement 很有辨识度：所有新站点默认包含 light/dark/system 三态主题切换，且做到完整（localStorage 持久化 + 系统偏好跟随 + ARIA radiogroup 语义）。

核心专长：

- CSS 设计系统：变量体系、4px 间距网格、字阶、语义化色彩命名
- 布局框架：容器系统、Grid/Flexbox 模式库、移动优先断点策略
- 信息架构：页面层级、视觉权重系统、交互模式定义
- 开发交接：优先级排序的实现指南 + 文件结构规范

## 什么时候雇佣他

| 场景 | 你能得到的产出 |
|------|--------------|
| 新项目不知道 CSS 怎么组织 | design-system.css + layout.css + 组件/工具类的完整文件架构 |
| 需要暗色模式 | light/dark/system 三态主题系统（CSS + JS + HTML 全套） |
- 信息架构混乱，用户找不到内容 | 页面层级与导航策略规格
| 开发团队反复纠结实现顺序 | 五步优先级实现指南（地基→布局→组件→内容→交互）|
| 多系统间的数据契约不清 | schema 合规与 API 契约定义 |

## 实战案例 1：营销站点的完整技术地基

背景：一个 5 人小团队要快速搭建产品官网，前端经验有限，不知道从哪开始。

你给他的输入：

```
我们要做一个 SaaS 产品官网：首页（hero/功能/价格/CTA）、
关于页、联系表单页。团队前端经验有限，需要能直接照着实现的地基。
要求支持暗色模式。
```

他会给你的产出（要点还原）：

1. CSS 变量系统一份，语义化命名防硬编码：

```css
:root {
  --bg-primary: #FFFFFF;
  --text-secondary: #6C757D;
  --space-1: 0.25rem;  /* 4px 网格 */
  --text-3xl: 1.875rem;
  --container-lg: 1024px;
}
[data-theme="dark"] { --bg-primary: #1A1A2E; /* ... */ }
@media (prefers-color-scheme: dark) {
  :root:not([data-theme="light"]) { /* 跟随系统 */ }
}
```

2. 布局框架：容器四档（640/768/1024/1280px）、hero 全屏、内容区双栏桌面/单栏移动。
3. 主题切换不是半成品：`ThemeManager` 类（localStorage 持久化 + 系统偏好监听）+ 带 `role="radiogroup"` 的三态切换 HTML——键盘与读屏用户同样可用。
4. 实现优先级指南：先 design-system 变量 → 再布局容器 → 再组件 → 再内容 → 最后交互润色。团队按顺序做，永远知道"下一步是什么"。

**价值**：前端经验有限的团队拿到的不只是代码片段，而是一套"决策已经做完"的施工图——这正是他的使命：消除架构决策疲劳。

## 实战案例 2：信息架构抢救

背景：一个内容型网站的导航有 11 个一级入口，用户测试显示 60% 用户找不到核心功能页。

雇佣他时可以这样提示：

```
我们的网站一级导航 11 项，用户迷失率 60%。
请重构信息架构与页面层级。
```

他会做的事：

1. 主导航砍到 5-7 项以内（他的信息架构规则），其余降级为二级或页脚。
2. 定义视觉权重系统：H1 最大字号最高对比 → CTA 高对比且在首屏与段落末 → 支撑内容（功能/价格/证言）的排布逻辑。
3. 交互模式规格：平滑滚动锚点、导航当前项指示、表单校验反馈与进度提示。
4. 交付含无障碍基线：键盘 tab 顺序、ARIA 标注、WCAG AA 对比度——作为架构的一部分而非补丁。

**价值**：把"导航太多了删几个"这种玄学操作，变成基于层级与权重系统的结构化重构。

## 使用技巧

- 把项目规格文档、任务清单给他（他的人设就是设计来读取 memory-bank 类文件的），他会先分析再动手。
- 明确说主题需求：默认他会给三态主题系统，如果你不需要暗色模式要提前说。
- 他交付的是"规格 + 示例代码"，落地实现可交给前端 agent；他的价值在决策而非代写全部代码。
- CSS 方法论（BEM/工具类/组件化）他都能适配，团队现有约定提前告知。

## 与其他 Agent 的接力

- 上游接收 **UI Designer**（`design-ui-designer.md`）的设计 token 与组件规范，他负责工程化为 CSS 架构。

- 信息架构的假设需要验证时，转给 **UX Researcher**（`design-ux-researcher.md`）做用户测试。
