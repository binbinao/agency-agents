# UX Researcher（用户体验研究员）使用指南

> 🔬 **一句话定位**：用真实用户数据取代设计假设——研究问题先行、方法有据、样本有统计学意义、结论可三角验证。

## 这位 Agent 是谁

UX Researcher 是用户行为研究与可用性验证专家。他的口头禅式风格是"Based on 25 user interviews and 300 survey responses, 80% of users struggled with..."——每个结论后面都跟着证据。他反对"确认偏误式研究"：先有结论再找数据，是他明确抵制的工作方式。

核心专长：

- 研究设计：研究问题 → 方法选择 → 样本量论证 → 偏差防护，一条龙方法论
- 定性研究：用户访谈、可用性测试（think-aloud 协议）、主题分析、亲和图
- 定量研究：问卷、A/B 测试、统计分析
- 产出物：用户画像（基于实证而非臆想）、用户旅程图（含情绪曲线）、优先级排序的研究建议
- 伦理规范：知情同意、隐私保护、多元化招募

## 什么时候雇佣他

| 场景 | 你能得到的产出 |
|------|--------------|
| 团队对用户需求各执一词 | 研究计划 + 访谈/问卷执行 + 有证据支撑的结论 |
| 新功能上线前心里没底 | 可用性测试协议（60 分钟结构化流程）+ 任务完成率/时长/错误数 |
| 用户画像停留在虚构 | 基于真实行为数据的 persona（每条洞察标注样本量） |
| A/B 测试不知怎么设计 | 假设 → 指标 → 样本量的统计严谨方案 |
| 产品要进国际市场 | 跨文化可用性研究与本地化验证 |

## 实战案例 1：优惠券功能上线前的可用性验证

背景：跨部门故事里的星舟科技，优惠券界面开发完成，Alex（Product Manager）要求上线前做可用性验证，回滚标准需要数据支撑。

你给他的输入：

```
商家后台新增优惠券功能（创建/发放/核销查看）。
目标用户：中小商家店主，年龄 35-55，非技术背景。
上线前需要可用性验证：商家能否 5 分钟内独立完成首次建券。
```

他会给你的产出（要点还原）：

1. 先立研究问题而不是直接发问卷："商家能否独立完成建券？卡点在哪个步骤？任务耗时多少？"——方法（8 人可用性测试）据此选择：探索性任务问题用小样本定性即可，统计性结论才需要大样本。
2. 60 分钟结构化会话：5 分钟开场与知情同意 → 10 分钟基线问题（当前怎么给老客打折）→ 35 分钟三个任务场景（建一张 9 折全店券 / 发给 30 天未下单客户 / 查看核销记录）→ 10 分钟事后访谈。
3. 量化 + 质性双轨数据：任务完成率、耗时、错误数（量化）；出声思考的原话、情绪反应（质性）。

```markdown
> "我以为'预算上限'是每天能花的钱，原来是总量……
> 这个词得改。"——53 岁服装店店主，任务 1 中
```

4. 建议按影响与成本排序："高优先级：'预算上限'标签改为'总量预算'并加帮助文本——8 人中 5 人在此犹豫超 30 秒；预计修改后任务完成时间降 40%。"

**价值**：上线前一周的 8 场测试，替团队拦下了"预算上限"这个自嗨术语——不测就上线，这会变成客服工单。

## 实战案例 2：用画像终结"用户想要什么"的办公室辩论

背景：产品会上，销售说商家要更多模板，工程师说商家要导出 Excel，吵不出结果。

雇佣他时可以这样提示：

```
团队对商家核心诉求有分歧。预算有限，两周窗口。
请设计一个能终结争论的研究方案。
```

他会做的事：

1. 把辩论转译成研究问题："商家在完成'老客唤回'目标时，模板与导出各扮演什么角色？"
2. 混合方法设计：12 个深度访谈（为什么）+ 300 份问卷（有多普遍），招募覆盖不同店龄/品类/城市层级——防样本偏差。
3. 产出画像带证据标签：每条洞察注明"基于 X 个访谈、Y 份问卷、Z 个行为数据点"，与臆想画像划清界限。
4. 交付一份决策友好的结论页：双方假设各自的证据强度、真实的用户排序、建议的下一步验证。

**价值**：他不裁决谁对谁错，他提供让错误假设无处遁形的证据结构。

## 使用技巧

- 说出预算与时间窗口，他会据此匹配方法（他的方法选择是被资源约束驱动的，不是越贵越好）。
- 招募标准说清楚（用户类型、地域、排除竞品从业者），他会补多元化要求。
- 他的建议输出自带成功指标（预计完成率提升多少），上线后记得回来对照——这也是他流程的一部分。
- 研究问题没想清楚时别急着要问卷，他的第一步永远是先帮你把问题问对。
