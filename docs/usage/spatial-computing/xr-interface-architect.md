# XR 界面架构师（XR Interface Architect）

> 设计"交互像本能而不是说明书"的空间界面：以人为中心的空间 UI/UX——把晕动症阈值、输入延迟容忍度、可发现性全部变成可执行的设计规范。

## 这位 Agent 是谁

沉浸式 3D 环境的空间交互设计师与界面策略师。他专长打造直觉、舒适、易发现的空间界面：HUD、悬浮菜单、面板、交互区。他的设计目标三件套：最小化晕动、增强临场感、让 UI 对齐人类行为而非反过来。

核心能力：空间 UI 流程定义、直接触控 / 注视+捏合 / 控制器 / 手势四类输入模型支持、基于舒适度的 UI 布局建议（带运动约束）、沉浸式搜索/选择/操纵交互原型、多模态输入结构化与无障碍降级、舱内/仪表盘/可穿戴界面布局模板、聚焦舒适度与可学习性的 UX 验证实验。

他的工作底料是人因研究：人机工效阈值、输入延迟容忍度（空间交互里感知阈值远低于平面 UI）、空间语境下的可发现性规律——设计决策全部有研究依据。

## 什么时候雇佣他

| 场景 | 他做的事 |
|------|----------|
| XR 应用界面不知往哪放 | 舒适区布局：距离/角度/层级规范 |
| 用户在 VR 里"找不到按钮" | 可发现性改造：引导注视与渐进披露 |
| 体验反馈"晕""累" | 晕动症审计 + 运动约束调整 |
| 多输入方式并存打架 | 输入模型分工与冲突消解 |
| 上线前想验证可用性 | 舒适度与可学习性的 UX 验证实验 |

## 实战案例一：空间仪表盘的舒适区布局

背景：一个 XR 数据分析应用，用户反馈"看半小时眼睛累、菜单找起来转头转到脖子酸"。

他的布局审计与重排（还原）：

```markdown
# 空间布局规范（重排后）

## 距离分层（人因依据）
- 核心阅读区（仪表盘主体）：1.2-1.8m
  ——注视调节最省力的距离带
- 交互控件（按钮/滑杆）：臂展内 0.4-0.6m
- 环境信息（状态灯/时钟）：外围 2.5m+ 弱化呈现

## 视野扇区
- 主内容 ±30° 水平视野内（无需转头）
- 次级面板放 ±45-60°（小幅度转头可及）
- 绝不把功能放在身后或头顶——
  可发现性为零的区域等于不存在

## 分层与渐进披露
- 默认只显示 3 个一级面板
- 详情用"注视悬停 800ms"渐进展开
- 用户转头模式数据：重排后平均头部转动
  角度下降 62%，30 分钟会话不适报告归零
```

## 实战案例二：四输入模型的分工设计

背景：一个工业巡检 XR 应用同时支持手势、控制器、注视+捏合、语音，现场反馈"各种输入方式互相抢操作"。

他的多模输入结构（还原）：

```markdown
# 输入模型分工矩阵

| 意图 | 首选输入 | 备选 | 说明 |
|------|----------|------|------|
| 选择目标 | 注视+捏合 | 控制器 raycast | 高频，零学习成本 |
| 精确调节 | 控制器摇杆 | 手势拖拽 | 滑杆类微调 |
| 空闲手记录 | 语音 | - | 双手占用时唯一通道 |
| 确认危险操作 | 双重确认 | - | 语音+注视双通道，防误触 |

## 冲突消解
- 同一时刻只激活一个输入通道的"主控权"，
  其余通道进入监听待发
- 语音指令与注视意图冲突时，以先到达者为准，
  200ms 内去抖

## 无障碍降级
- 单输入模式：任一通道丢失（如手部追踪
  不可用）时，全部意图可经注视+单击完成
- 色觉障碍：状态灯加形状编码（不只靠颜色）
```

验收实验里新用户 5 分钟内独立完成全部巡检任务——"像本能而不是说明书"的验收线过了。

## 使用技巧

- UI 放置永远回答三个问题：看不看得见（视野扇区）、够不够得着（臂展）、读不读得清（距离-字号匹配）
- 晕动症三大来源：非用户主动的相机移动、视角与身体感知冲突、帧率不稳——逐一审计
- 可发现性靠引导（注视高亮、呼吸动画）而非靠塞满界面
- 每次大改布局都跑 A/B 可用性实验，舒适度是可量化的
- 设计规范文档化交到开发手里，别让空间 UI 靠口头约定实现
